# Huetype

Tauri v2 desktop app (Windows first) for picking colors and identifying fonts from anywhere on screen, plus 21 color, font and design-system reference sections.

- Feature spec: https://claude.ai/artifact/HdMre9X6c3rZEUFnwpSCvz
- UI mockups: https://claude.ai/artifact/2KLHspqnq7HtQUpy2mVyAf
- Roadmap and current step: `docs/ROADMAP.md` (read this first; it is the source of truth for what is done and what is next)

## Decisions (agreed with Subbu, 2026-11-01)

- Name **Huetype**. Theme: light and dark; default follows Windows. The floating picker toolbar and loupe are always dark.
- Frontend React + TypeScript + Vite. Backend Rust (Tauri v2).
- v1 targets **Windows 10/11 only**. Keep OS-specific code (screen capture, OCR, accessibility) behind a trait or `cfg` module so macOS/Linux can be added later.
- Pantone section = Color of the Year only, 2002 to 2026.
- Font identify is offline in v1 (no AI/cloud). Google Fonts only, with "closest alternative" wording for other fonts.
- One app window only (`main`). The picker toolbar and capture overlay are transient helper windows. Closing `main` hides it to the tray; Quit is in the tray menu.
- Default global shortcuts are **Ctrl+Alt+C** (pick color), **Ctrl+Alt+F** (identify font), **Ctrl+Alt+Space** (toolbar). Not Ctrl+Shift: Ctrl+Shift+C is browser DevTools. A shortcut another app owns is reported in Settings, never fatal. Users can rebind in Settings; choices are stored as `shortcut.<action>` settings rows and re-applied by the main window on load (`applySavedShortcuts`).
- Screen coordinates are physical pixels on the virtual desktop (same space as `cursor_position()`; monitors can have negative origins and different scale factors). Sampling captures only a small square around the point via xcap (GDI on Windows, default features off), never a full screen, and averages in sRGB (1, 3, 5 up to 25 px squares).
- Picking: each pick session hides our own windows, freezes every monitor (full capture), and covers each monitor with an overlay window `overlay-<n>` (created once, then hidden and reused). Click adds and keeps the session open (multi-pick); Shift+drag averages; arrows nudge 1 px (Shift 10); Enter picks; Esc, right-click or Alt+F4 ends. Picks are broadcast as `huetype://picked`.
- Pick history: the main window (always loaded, even hidden) records every pick in the SQLite `picks` table (kept to the newest 500), copies it in the copy format (`picker.format` setting: hex, rgb, hsl or oklch; changed from the toolbar's format chip), and refreshes the tray's "Recent colors" menu via `set_recent_picks`. Other windows only read history. Color math is culori (`src/lib/colors.ts`): nearest CSS name by CIEDE2000, WCAG 2 contrast.
- Picked colors (6.2, 6.3, Subbu 2026-11-02): during a color pick each overlay shows a session bar at the bottom (`src/overlay/SessionBar.tsx`): every color picked this session in order (from the `huetype://picked` event, so all monitors agree), a hover card and a Close button (same as Esc); mouse events stop at the bar so it never picks. The hover card (`src/picker-ui/ValueCard.tsx`, always dark) is shared with the toolbar (now 5 swatches, opens on hover or click): HEX, RGB, RGBA, HSL, HSB with copy, and "Color details". Values, description, tints/shades (OKLab mix towards white/black) and harmonies come from `src/lib/colorDetails.ts`. Color details is the `color` section at `#/color/<HEX>` (`useHashRoute` passes the argument); other windows open it with the `open_color` command (validated hex). Its actions hand the color to Scales, Color pairing and Contrast through their remembered-input keys, and to Palettes through the one-shot `huetype.palettes.seed` key.
- The toolbar window grows upward by `POPOVER_HEIGHT` while a swatch popover is open (`toolbar_popover`), so the pill never moves and no transparent area blocks clicks the rest of the time.
- Converter: input is anything CSS parses plus bare hex and `r, g, b` triplets. Colors outside sRGB keep their exact Lab/LCH/OKLab/OKLCH/P3 values; sRGB-based formats (HEX, RGB, HSL, HWB, HSV, CMYK) show the color gamut-mapped by reducing OKLCH chroma, and the page says so. HSV and CMYK are labelled "not CSS"; CMYK is the naive device-independent formula.
- Contrast: WCAG 2.2 ratio (culori) and APCA-W3 0.0.98G-4g (own implementation in `src/lib/contrast.ts`, tested against the published reference values). "Nearest passing color" moves one color's OKLCH lightness (hue kept, chroma clamped to sRGB) by binary search, for text or background, lighter or darker.
- Palettes: generated in OKLCH (`src/lib/palette.ts`, pure and seedable): harmony sets hue offsets, lightness runs dark to light so every palette has contrast inside it, chroma is tapered at the extremes and clamped to sRGB. The first locked color anchors hue and chroma. 3 to 8 colors; Space generates (not while typing or on a button). Saved palettes are rows in the SQLite `palettes` table (migration 3, colors as a JSON hex array; `src/lib/palettes.ts`).
- Scales: `src/lib/scale.ts` makes 50 to 950 in OKLCH from per-step lightness and relative-chroma tables shaped like Tailwind's. The base color is kept exactly at the step with the nearest lightness; other steps are shifted by its lightness offset, fading to zero at both ends, so the scale stays monotonic. Chroma is clamped to sRGB. Yellows (hue 50 to 115) lean darker steps towards orange. Default name is the Tailwind hue family. Export: CSS vars, Tailwind v4 `@theme`, Tailwind v3 config, JSON, values in HEX or OKLCH.
- Color pairing: `src/lib/pairing.ts`, seven pairings (complementary, analogous, split, triadic, square, rectangle, monochromatic). Default wheel is OKLCH (partners keep the base's lightness and chroma, clamped to sRGB); an HSL wheel toggle gives the classic answers (red pairs with cyan). Grays get a note, since they have no hue.
- Color blindness: `src/lib/vision.ts`. Protan/deutan/tritan use the Machado 2009 full-severity matrices in linear sRGB; lower severity (anomalous trichromacy) blends with identity. Achromatopsia and grayscale print keep luminance only. Situations (dim screen, glare, night light) are labelled approximations. Two colors "look the same" under CIEDE2000 5 and are "hard to tell apart" under 11. Input is 2 to 8 colors; with exactly 2 the page also shows text contrast.
- CSS generator: `src/lib/cssgen.ts`. Up to 6 named colors (first = primary, second = accent role), each gets a scale; optional neutral is a gray tinted with the primary hue. Semantic roles are shadcn-style names (background, foreground, primary, primary-foreground, secondary, accent, muted, border, ring, ...) for light and dark; dark applies with `prefers-color-scheme` or a `.dark` class. Formats: CSS vars, Tailwind v4 `@theme`, Tailwind v3 config (a role named like a scale becomes its `DEFAULT`), SCSS, W3C DTCG tokens JSON, Material 3 roles (tones are exact CIELAB L* like HCT; hue and chroma from CIELCh, not CAM16).
- Image palette: `src/lib/imagePalette.ts`, k-means (k-means++ seeding, seeded) in OKLab on at most 12,000 evenly spaced opaque pixels of the image scaled to 1200 px; 3 to 8 colors (8 = Palettes max, so results save as a palette). Sources: drop, paste, file, or `grab_screen` (Rust, `picker.rs`: hides our windows, captures the monitor under the main window via `capture_monitor_at`, same binary frame as the overlay). Images never leave the machine.
- Saved library: `src/lib/library.ts`. Starred colors are rows in the SQLite `saved_colors` table (migration 4, hex unique and uppercase, optional note up to 200 chars); saved palettes stay in `palettes`. Any window may star (the toolbar popover too); every change to either table broadcasts `huetype://library-changed` so open pages refresh (`src/useStarred.ts`, `components/StarButton.tsx`). The Saved page opens a palette in Palettes through a one-shot localStorage key (`requestOpenPalette` / `takeOpenRequest`). "Copy library as JSON" exports `{app, version: 1, colors, palettes, fonts, gradients, designSystems}` (each gradient with its CSS and model).
- Font catalog: `src/lib/fonts.ts`. A snapshot of every Google Fonts family (minus Material Symbols icon fonts) ships as `src/data/google-fonts.json`, built by `npm run fonts:catalog [version]` (`scripts/font-catalog.mjs`) from the Developer API data in the google-font-metadata npm package, so no key is needed and it works offline. An optional Google Fonts Developer API key (Settings, `fonts.apiKey` setting) refreshes it with `sort=popularity&capability=VF`; that copy is cached in the SQLite `cache` table (migration 5, key `fonts.catalog`) and carries `rank`, which enables "Most popular". CSP allows `connect-src https://www.googleapis.com`. Previews load one css2 stylesheet per family and weight as cards scroll into view; copy actions give `font-family` with the category fallback (handwriting = cursive), `<link>` tags and `@import`. Starred fonts are rows in `saved_fonts` (migration 5) and part of the Saved page and JSON export.
- Top, curated and pairing: `src/lib/fontSets.ts` over our own JSON in `src/data/` (`top-fonts.json`, `curated-fonts.json`, `font-pairs.json`; a test checks every name exists in the catalog). Top fonts uses live API rank when the catalog has it, else our curated top list (labelled as such); Trending needs the API (`sort=trending`, stored as `trend`), else the page shows "Recently updated". With a key saved, the main window refreshes a cached catalog older than 7 days on load (`refreshIfStale`). Pairing suggests bodies for a heading: curated pairs first (either direction), then `BODY_FONTS` picks by category contrast (serif heading gets sans bodies; sans gets serif then sans; display, handwriting and mono get sans then serif) ranked by regular, bold and italic support. Other pages open Font pairing with a family through the one-shot `huetype.pairing.heading` localStorage key (`requestPairing`). Shared card: `components/FontCard.tsx`.
- Font identify capture: `src-tauri/src/fontid/` (`TextReader` OCR and `FontProbe` traits; `windows.rs` uses Windows.Media.Ocr with the user profile languages, else en-US, and UI Automation; other OSes get `Unsupported` stubs). The pick session has `Mode::Font`: the overlay drags a box (at least 6 px), `overlay_font_region` crops it from the frozen frame, closes the overlays, waits for them to hide, then asks UIA for the font name and size at the box center (exact, only when the app exposes a text pattern) and runs OCR on the crop upscaled so text is about 48 px tall (word boxes mapped back). The result is kept in the session (`font_capture`, `font_capture_image`), the main window opens the `identify` section and `huetype://font-captured` is broadcast. Matching against Google Fonts is below.
- Font matching (offline): `npm run fonts:index` (`scripts/font-index.mjs`, rasterizer `scripts/raster.mjs`, opentype.js) renders a–z, A–Z, 0–9 of every Latin Google Font (regular, plus 700 for our popular lists; Noto script families skipped) from the Latin-subset TTFs that google-font-metadata lists, and writes `public/font-index.bin` (about 3.6 MB; exact duplicates dropped and recorded in `src/data/font-index-aliases.json`). `src/lib/glyphFeatures.ts` is shared by the script and the app (Node loads it directly): each letter is an 8 x 8 grid of average ink in its ink box plus log width and height relative to the x-height. `src/lib/fontMatch.ts` cuts OCR words into letters (connected pieces, dots joined, thresholds 0.35 then 0.15 then 0.6; a word whose pieces do not match its text is skipped), averages repeated letters and ranks families by mean letter distance; our top list wins near-ties (x0.95) because many families copy a popular one's letters. Labels: "Likely match" (leader only, under 0.09 + 0.6/x-height and 5% ahead), "Possible match" (under 0.16 + 1/x-height and within 25% of the leader), else "Closest alternative"; a non-Google font named by UIA gets our `src/data/font-alternatives.json` stand-ins first, then shape matches labelled as alternatives. Measured on Chromium-rendered text at 14 to 40 px: popular fonts 94% right first, bold 100%, all in the top 5; joined scripts cannot be split.
- Pantone (4): `src/data/pantone-coty.json` (our own list, 2002 to 2026; 2016 and 2021 have two colors; TCX codes, commonly published sRGB hex approximations, our own one-line notes) read by `src/lib/pantone.ts`. The page shows a year strip, the selected year's colors (values in every copy format, contrast on white and black, star), all years by decade, "Copy all as CSS variables" (`--coty-<year>-<name>`), and a trademark and approximation note. The last viewed year is kept in localStorage (`huetype.pantone.year`).
- Curated colors (7) and Brand colors (8): `src/lib/colorSets.ts` over our own `src/data/curated-colors.json` (8 mood collections, 6 palettes of 5 colors each) and `src/data/brand-colors.json` (56 brands, HEX only, no logos; `guide` is the official brand guidelines URL when one is public, else `site`; the page labels the link accordingly and notes values should be checked against the guidelines). Search matches names, color names and hex. Clicking a swatch copies it in the app copy format (`src/useCopyFormat.ts`); swatch text ink comes from `src/lib/colorInk.ts`. "Open in Palettes" saves the palette and hands it over with `requestOpenPalette`. Brand "Copy CSS" gives `--<brand>-<color>` variables.
- Gradients (9): `src/lib/gradient.ts` is the pure model (linear, radial with circle/ellipse and center, conic with start angle and center; 2 to 10 stops at 0 to 100%; mixing space OKLab by default, OKLCH or sRGB). CSS uses CSS Color 4 `in <space>`; the copied CSS adds an sRGB fallback line first, with 3 extra stops per gap sampled from the same mix (culori), so it looks the same where `in` is not supported. Adding a stop puts it in the widest gap (or where the bar is clicked) with the color already shown there. Exports: CSS background, Tailwind arbitrary class, JSON. Curated set is our own `src/data/curated-gradients.json` read by `src/lib/gradientSets.ts`. Saved gradients are rows in the SQLite `gradients` table (migration 6, normalized model as JSON; `src/lib/gradients.ts`), shown on the Saved page; Saved opens one in the editor with the one-shot `huetype.gradients.open` key (`requestOpenGradient`). The editor keeps the current gradient in localStorage (`huetype.gradients.current`).
- Guess the color (12): `src/lib/guess.ts`, pure and seeded (mulberry32 from `palette.ts`). A puzzle shows 4 colors stepping evenly through one OKLCH axis (hue, lightness or chroma, labelled Saturation) and offers 5 options; every color is inside sRGB without clamping (plans are retried), so steps stay exact. Wrong options are part steps on the same axis or the right step drifted on another axis, at least CIEDE2000 3 apart, and get closer through the round. Points: 100 for the answer, else max(0, 90 - 7 x ΔE2000). A round is 10 puzzles, axes equally often. The daily round seeds from the local date (FNV-1a), the same for everyone; only the first daily result of a date counts. Stats (rounds, best score, best streak of exact answers, daily results for 60 days) are one JSON settings row, `guess.stats`. Keys: 1 to 5 pick, Enter goes on. "Copy result" gives a score line plus one square per puzzle.
- Design systems (19 to 21): `src/lib/designSystems.ts`. Curated (20) is our own `src/data/curated-design-systems.json` (29 public systems: name, org, our own description, platforms, tags, links to the system's home page and source repo only, since deep links move). My design systems (21) are rows in the SQLite `design_systems` table (migration 7; links, tags, colors and fonts as JSON arrays; `source` is the curated id when copied with "Add to mine"). `cleanDraft` trims and limits fields, keeps only http(s) links (a bare host gets https), dedupes tags case-insensitively and normalizes colors to uppercase hex; the editor refuses to save with an invalid link. Colors can come from Saved; fonts suggest from the catalog but any name is allowed. Delete asks inline (Delete / Keep), no browser dialog. Overview (19) searches both lists and shows "recently opened" (a link followed or an entry opened; `huetype.ds.recent` in localStorage, 8 refs `curated:<id>` / `my:<id>`). Pages hand an entry to the editor with the one-shot `huetype.ds.edit` key (`requestEdit`). Changes broadcast the library event; the library JSON export includes `designSystems`. Links open with `openExternal`.
- Branding (5.1): the app icon is a rounded square with the brand conic gradient (`#ff6a88, #f2b84b, #3ccf8e, #7c8cff`, from 200deg) and a white loupe ring around a dark dot; the sidebar `.brand-mark` is the same mark. `npm run icon` (`scripts/app-icon.cjs`, Playwright) renders `src-tauri/icons/app-icon.png`, runs `tauri icon`, drops the Android/iOS sizes and copies `public/favicon.png`. Never edit the generated sizes by hand. The tray uses the default window icon.
- Release (Phase 5): installers stay unsigned for now (Subbu, 2026-11-01), so Windows SmartScreen warns on first run; signing is step 5.4. The auto-updater (5.3) is deferred too (Subbu, 2026-11-02): while he is the only user, updating means running the new installer over the old one, which keeps all data. Pushing a `v<version>` tag runs `.github/workflows/release.yml` (tauri-action): it checks the tag against every version file (`scripts/version.mjs`; `npm run release:version set x.y.z` sets them all), tests, and attaches the NSIS `.exe` (per-user, no admin) and MSI to a draft release; a manual run uploads them as an artifact. Steps are in `docs/RELEASING.md`.
- Navigation (6.1, Subbu 2026-11-02): no section numbers anywhere in the UI. Sidebar groups are Picker, Create, Check, Discover, Fonts, Design systems (`GROUPS` in `src/sections.ts`). The numbers in this file and the spec are references only.
- Dev server (6.4): Vite listens on `127.0.0.1:1420` and `devUrl` points at the same address, never `localhost`, because on some Windows setups `localhost` resolves to IPv6 `::1` and the dev window shows "localhost refused to connect". `TAURI_DEV_HOST` still overrides the host for mobile dev.
- Curated datasets are our own JSON in the repo; do not scrape colorsinspo.com or similar sites.

## How work is done

- Work in small steps, one branch and one PR per step: `phase-<n>/step-<m>-<slug>`.
- At the end of each step, tick it in `docs/ROADMAP.md` and add any new decision here.
- Before pushing: `npm run build` (tsc + vite), `npm test` (vitest, `src/**/*.test.ts`), and `cargo clippy` + `cargo test` in `src-tauri`. CI runs the same on `windows-latest`.

## Layout

- `src/sections.ts`: the single list of all sections (sidebar, routing, placeholders read it).
- `src/pages/`: one component per section as they get built (`PickerHome`, `ContrastPage`, `ConverterPage`, `ColorNamesPage`, `PalettesPage`, `ScalesPage`, `PairingPage`, `VisionPage`, `CssGeneratorPage`, `ImagePalettePage`, `SavedPage`, `FontListingPage`, `TopFontsPage`, `CuratedFontsPage`, `FontPairingPage`, `IdentifyFontPage`, `PantonePage`, `CuratedColorsPage`, `BrandColorsPage`, `GradientsPage`, `GuessPage`, `DesignSystemsHubPage`, `CuratedDesignSystemsPage`, `MyDesignSystemsPage`, `SettingsPage`), routed in `src/App.tsx`; `components/PageHead.tsx` renders the numbered title. `src/components/`: shared UI.
- `src/styles.css`: design tokens (light base, dark override) and app styles.
- `src/lib/`: frontend services. `db.ts` (shared SQLite connection), `settings.ts` (key/value settings, localStorage fallback outside Tauri), `autostart.ts`, `env.ts` (`isTauri()`).
- `src/SettingsContext.tsx`: settings state for the app, applies the theme.
- `toolbar.html` + `src/toolbar/`: the floating toolbar page (second Vite entry, always dark, own CSS). Its window is created in `src-tauri/src/toolbar.rs`; `capabilities/toolbar.json` scopes what it may call.
- `src-tauri/src/shortcuts.rs`: global shortcut registry (`shortcut_status`, `set_shortcut` commands; accelerators like `Ctrl+Alt+KeyC`). Frontend side: `src/lib/shortcuts.ts`, `src/components/ShortcutRow.tsx`.
- `src-tauri/src/capture/`: `mod.rs` has the `ScreenSource` trait (OS side; `XcapSource` today), `sample_point`, and the `color_at_point` / `color_at_cursor` commands. `sampler.rs` is pure pixel math (pixel, area average), unit tested. Building on Linux needs `libpipewire-0.3-dev` (xcap).
- `src-tauri/src/picker.rs`: the pick session (`start`, `finish`, overlay windows, `start_pick` / `overlay_*` commands, frame sent as binary: 20-byte header + RGBA). `overlay.html` + `src/overlay/` is the overlay page (third Vite entry, always dark; `pixels.ts` mirrors `sampler.rs`). `src/lib/picker.ts` is the frontend API (`startPick`, `onPick`, `onPickerError`).
- `src/lib/colors.ts` (formats, nearest name, contrast, copy format, clipboard, `parseColor` / `convert` for the Converter, `NAMED_COLORS`), `src/lib/history.ts` (pick history), `src/lib/palette.ts` (palette generator, export) `src/lib/palettes.ts` (saved palettes), `src/lib/scale.ts` (scales), `src/lib/pairing.ts` (color pairing), `src/lib/vision.ts` (color blindness), `src/lib/cssgen.ts` (CSS generator), `src/lib/imagePalette.ts` (image palette), `src/lib/library.ts` (starred colors and fonts, library events, export), `src/lib/fonts.ts` (font catalog, filters, CSS), `src/lib/fontSets.ts` (top, collections, pairing), `src/lib/open.ts` (open a URL in the browser), `src/lib/pantone.ts` (Color of the Year data), `src/lib/colorSets.ts` (curated collections and brand colors), `src/lib/colorInk.ts` (text color on a swatch), `src/lib/gradient.ts` + `src/lib/gradients.ts` + `src/lib/gradientSets.ts` (gradients), `src/lib/guess.ts` (Guess the color), `src/lib/designSystems.ts` + `src/useMyDesignSystems.ts` + `components/DsLinks.tsx` (design systems), `src/lib/fontIdentify.ts` (font capture API and notes), `src/lib/glyphFeatures.ts` + `src/lib/fontMatch.ts` (font matching), `src/usePickRecorder.ts` (main window recorder). Toolbar popover: `src/toolbar/Popover.tsx`.
- `src-tauri/src/lib.rs`: app setup, window behavior, `open_section()` (tray to page navigation via the `huetype://navigate` event). `tray.rs`: tray icon and menu. `db.rs`: SQLite migrations (append-only; add a new version, never edit a released one).

## Storage

- One SQLite file, `huetype.db`, in the app config dir. Schema changes go in `src-tauri/src/db.rs` as a new migration.
- Settings are key/value rows in `settings`. Launch-at-startup is not stored there: the OS autostart entry is the source of truth.
- Window position and size are remembered by tauri-plugin-window-state (position/size only, never visibility).
- The main window starts hidden (`visible: false`) and is shown in `setup` unless launched with `--hidden` (the autostart entry passes it).
